# 字字岛 · 用户体验抽查评审 PT1（家长的讲解设置 + 教一教，第 1 轮）

评审对象：`review/PT1/index.html`（与主工程 `index.html`、`src/` 逐字节一致；sw.js VERSION `v7b6972b7`，`tools/gen_sw_list.py --check` 通过）。
评审方式：读 `docs/DESIGN.md`、`docs/OPTIONS-EXPLAIN-SPEC.md`、`docs/DELIVERY.md` 和两次提交（`71c9979`、`d8d15fe`）的 diff，再用 Playwright 自己操作（真实鼠标点 ▶ 下一步、长按齿轮、旋转视口、切后台），脚本 `tests/review_pt1.py`（新文件，没有改 app 代码），截图和数据在 `tests/logs/pt1/`，日志 `tests/logs/pt1_*.log|txt`。

## 1. 总体结论

两项功能都按委托方的意思做出来了，而且做得比较扎实：

- **答错后的讲解**三档都生效、能存住、坏值回落到"自动"。**一步一步**在 84 个游戏 × 三种尺寸都真的停：每一拍都等家长点 ▶ 下一步，闲置 25 秒不自己走，孩子点选项、点屏幕、点主持人、点"跳过"手势都不往下走；关、自动没有回归（原 `test_options.py` 03/05/06 全过，420 次答错讲解正常）。
- **教一教**确实降级、确实什么都不记：整局（4 对 1 错）打完，存档除了一个出题去重用的 `lastKey` 一字不变（星、级别、played、记忆箱、learned、missNext、当天题数全没动），不插复习卡、不插错题卡、写字不记 learned 也不进描红兜底，钥匙局永远不是教的局，离开就关、"教"字标记在星星托盘旁边，只能从长按齿轮进。

但有一个**会把家长卡住的真问题**：一步一步等待时如果 iPad 转了方向，▶ 下一步和"跳过"留在旧坐标、跑到屏幕外，点哪里都不动，只能转回去或回家。委托方提的检查项里明写了"旋转时不卡住"，这条没过。另有一个中等问题（数一数、十格灯的逐个计数在一步一步里被切碎）和一个中低问题（讲得慢的局会被 3 分钟规则提前结束）。所以这一轮不能通过，修好后应该很接近通过。

## 2. 问题（按严重程度）

### P1（高）一步一步等待中旋转屏幕，▶ 下一步 / 跳过 跑到屏幕外，流程卡死

- **现象**：横屏 1180×820 等第 1 拍时按钮在 (1042, 379)。把视口改成竖屏 820×1180 后，按钮仍在 (1041, 378)、"跳过"在 (1060, 321)，都在 820 宽的屏幕外。点屏幕任何地方 `stepN=0, stepWaiting=true` 不变。竖屏→横屏同样：竖屏时按钮在 (350, 1042)，转到 820 高后仍在 y=1041，屏幕外。只有转回去（按钮立刻能点）或点回家能脱困。
- **证据**：`tests/logs/pt1_interrupt.log` 的 "rotate L->P / P->L" 两条 FAIL 和 "STUCK after L->P" 行；截图 `tests/logs/pt1/rotate_wait.jpg`（竖屏画面里没有任何绿色按钮）。
- **原因**：`src/app.js` 里 `Step.place(st)` 只在 `mount` 和每拍 `pause` 开头算一次位置；`Session.mount` 的 `Stage.onRelayout` 只调 `game.layout`、`K.relayoutChrome`、`relayoutQ`，没有重新放置步进按钮。
- **建议**：在 `Stage.onRelayout` 里（或 `K.relayoutChrome`）加一句 `if (st.step) Step.place(st)`；再把"跳过"和"下一步"都限制在 `#game` 的边界内（clamp）。顺带：`Step.place` 的障碍物列表里没有 `#teachb`，右上角备选位 y=130 会和 92–148 的"教"字重叠。

### P2（中）一步一步把"逐个计数"的演示切碎：数一数、十格灯

- **现象**（真实速度）：自动模式下数一数 4 个草莓的计数音间隔 208/206/209 ms、十格灯 9 盏灯 165–169 ms，均匀地"1、2、3、4"。一步一步里变成：数 1 → 弹出 ▶ 下一步等家长点 → 2、3、4 以 83 ms 一口气蹦完；十格灯是 1 →[点]→ 2 3 4 →[点]→ 5 6 7 →[点]→ 8 9。家长在数到一半时被要求点"下一步"，而且剩下几个数挤成一团，演示"为什么是四"的核心一拍反而看不清。字母排队的小火车逐块跳也同理（全部瞬间一起跳）。
- **证据**：`tests/logs/pt1_real.log`（`hulk3:quiz` gaps `[1632, 83, 83]`、`thor3:quiz` gaps `[..., 1618, 85, 86, 1619, 86, 84, 1620, 85]`）；对照脚本输出：自动 `[208, 206, 209]` / `[168, 169, 165, ...]`。
- **原因**：`src/games.js` `EX.wait(st, ms)` 在步进模式下整个被 `Step.pause(st)` 取代：要么停下等点，要么（上次点后不到 250 ms 且没有新东西）什么也不等，原来的 `ms` 从不执行；`Sfx.count` + `scope.anim` 本身没标 `stepDirty`，所以靠 250 ms 的时间阈值随机切。
- **建议**：步进模式下 `EX.wait` 先 `await st.scope.wait(ms)` 再决定要不要 `pause`；循环里的逐个计数算"一次演示"，整段数完再停一次（例如在循环前 `st.stepHold = true`，循环后 `stepDirty = true; await Step.pause`）。

### P3（中低）讲得慢的一局会被 3 分钟规则提前结束，只出 3 题

- **现象**：`Session.start` 里 `if (G.round >= 3 && Clock.t() - G.t0 > 180000 && !fast() && !G.key) break;`。真实速度下把时钟拨快 200 秒后，一局 5 题只出了 3 题就"玩得真开心"回地图。一步一步没有时间限制、家长一拍一拍讲，一局讲到 3 分钟很正常；孩子答对的第 4、5 题的星这局拿不到，家长也不知道为什么突然结束。教一教的局（家长讲得多）同样受影响。
- **证据**：`tests/logs/pt1_real.log` "OBS real speed: a session already past 3 minutes ends after 3 questions (back on map=True)"。
- **建议**：讲解（尤其 `stepWaiting`）的时间不计入这 3 分钟（例如在 `Step.pause` 期间累加一个 `G.stepMs`，判断时减掉），或者一步一步模式下不启用这条规则。

### P4（低）写字/写字母的讲解在一步一步里只有一拍，缺了一笔有一拍是空的

- 写字（含写字母）的讲解是金圈 + "看，是这样" + 毛笔补写滑掉的那一笔，三件事同时发生后才停一次（快速模式 1 拍；真实速度 2 拍，第 2 拍什么也没发生，是 `runQ` 末尾多出的空停）。委托方要"每句话、每个圈、每个演示动作都停"，这里圈和示范没分开。缺了一笔的第 2 拍也是空的（选的那一笔飞回原位时 `EX.cards` 的 gap 又停了一次）。字母排队第 1 拍后按钮从右上 (1042,188) 跳到底部正中 (530,682)，其余抽到的游戏按钮位置都稳定。
- 证据：`tests/logs/pt1/sweep_*_L2.json` 的 `said` 字段（`*:write`、`*:abc` 都是 1 拍），`pt1_real.log`（`peppa:write` 2 拍、第 2 拍 `[]`；`huluwa:quiz` 第 2 拍 `[]`），位置数据见本评审最后一段脚本输出。
- 建议：`WriteBase.explain` 在金圈后、示范前各 `await EX.wait`；空拍可以在 `Step.pause` 里把"自上次点击以来没有新 `stepDirty` 且没有新语音"直接跳过（现在 250 ms 阈值太短）。

### P5（低）竖屏时"跳过"小按钮压住田字格金圈的一角

- 820×1180 的所有写字局，"跳过"(84×44) 落在田字格金圈的右下角上（重叠约 1386 px² 卡片、1628 px² 金圈）；数一数 L4 竖屏时也擦到选项卡 168 px²。▶ 下一步本身在三种尺寸、84 个游戏都 ≥ 88 px、在屏内、在最上层、不压选项和角色。
- 证据：`tests/logs/pt1_sweep_820x1180.log` 的 overlap 列表；截图 `tests/logs/pt1/peppa-write_L2_820x1180_s1.jpg`、`teach_step_P_s2.jpg`。
- 原因：竖屏写字时六个备选位都和田字格或角色有重叠，`Step.place` 取重叠最小的一个，整块 120×178 的顶部（就是"跳过"）仍压到金圈一角。建议：备选位加上离圈/选项的安全边距，或放不下时把"跳过"挪到按钮下方/侧面。

### P6（低）家长面板文案与实际位置不符

- 面板说"右边小小的'跳过'是给家长的"，`DESIGN.md` 说"旁边"，实际"跳过"在 ▶ 下一步的**正上方**。改成"上方"即可。

### P7（低）教一教只存在内存里，iPad 常见的页面重载会悄悄关掉

- `Teach.on` 不存档，代码注释也写明 reload 结束它。但 iPadOS 的 Safari/PWA 切到别的 app 再回来经常重载页面；家长在面板里设好、孩子过几分钟再点进去，可能已经按原难度出题（有"教"字可辨认，但家长不一定看）。另外教一教对游戏 A 设好后，孩子先玩了 B，A 仍然处于"待教"状态（观察到 `Teach.on` 不变），和面板文案"离开这个游戏就自动关掉"的直觉略有出入。
- 建议：把 `Teach.on` 存进 `settings`（进那个游戏后照旧"离开就关"），或在面板文案里说明"关掉 app 会取消"。

### 观察（不扣分）

- "跳过"按 spec 故意做小（84×44）给家长用，但 4 岁孩子完全够得到、点得中，而且它就在孩子会去点的大绿按钮上方；如果委托方在意"孩子点不跳过"，可以要求长按。
- 讲解等待中点主持人头像仍会"再听一遍"题目（`Session.relisten`），把正在讲的句子打断。自动模式原来也是这样，不是这次引入的。
- 开发方说明"先上线、后测试"：这两项功能没有自己的自动化测试（`tests/` 里没有一步一步、教一教的用例）。建议把本评审的 `tests/review_pt1.py` 的 sweep / interrupt / teach 三部分转成正式测试，尤其加上旋转。
