# 字字岛 · 用户体验评审 R1

评审人：Fable 5.1（high）。对象：本目录 `index.html`（字字岛 1.0）。方式：Playwright 在 1180×820 横屏和 820×1180 竖屏（另抽 1024×768）亲眼看截图、真实时长下听语音队列、驱动孩子的手势；代码只在找原因时查。所有截图在 `tests/logs/shots/`（56 个小游戏 × 两个方向）、`tests/logs/screens/`（首页、地图、岛面板、字宝盒、大结局）、`tests/logs/review/`（本次评审专门拍的写字、答错、不操作、无解题）。

## 1. 总体结论

这是一套做得很用心、美术统一、规则守得住的识字写字 app：写字引擎（绿点 + 数字 + 箭头 + 毛笔示范，判起笔、方向、形状、顺序）对 4 岁孩子是看得懂、写得出的，"字活过来"的那一刻好看，530 句录音一句不缺，故意不操作 60 秒没有任何替孩子做的动作，答错换新题不给星。但有两类推理挑战会出"无解题"（"哪个写对了"里 B/C/D/E/K 上下翻转、N/S/Z 旋转 180° 后和正确答案长得一模一样，14%–33% 的题只能靠猜；"缺了一笔"29% 的题里有和答案同名同形的笔画选项），四个字的笔画名念错（禾、米、休的最后一笔是捺不是点，小的第二笔是撇不是点），认字 L1 和 L2 完全一样、L3 以后卡住再久也不给图。这些不是打磨问题，是内容正确性问题，年度 App 的水准不会把它们放出去。修掉以后，这个 app 有 9 分的底子。

## 2. 问题（按严重程度）

**[严重] R1-01 "哪个写对了"（光之国挑战）会出两张一模一样的卡，孩子选对了也被判错**
证据：`tests/logs/shots/P_ultra_quiz.png`：三张卡 "ꓭ、B、B"——中间那张是 B 上下翻转（scaleY(-1)），B 上下对称，翻完还是 B，只是在卡片里位置偏低；`tests/logs/review/dup_mirror.png`：S 的 "ok / flipX / flipY" 三张，S 上下翻转后和正的 S 肉眼无法区分。按字母几何算过（`rv_dup.json` mirror_similarity）：B、C、D、E、K 的上下翻转、N、S、Z 的旋转 180° 与原字母的点距 ≤ 2.5（字母单位，等于重合）。用游戏自己的出题函数生成 300 题统计：L1 43/300、L2 99/300、L3 75/300、L4 86/300、L5 88/300 的题含有这样一个"假错项"。孩子点了那张看起来正确的 B，听到的是"它翻跟头啦"，星星没了。这违反"星星只给第一次做对"的公平前提，反馈也不"就事论事"（它明明没翻）。
→ 建议：按字母排除与它自身重合的变换（B C D E K 不出 flipY；N S Z 不出 rot；汉字同理检查 上/下/工 类），变换绕字形自身中心做（现在绕 svg 中心翻，字形会掉到卡片下半截，既是位置提示也像排版错）。加一条自测：生成 1000 题，任何错项与正解的点距 < 3 即失败。

**[中等] R1-02 "缺了一笔"（葫芦山挑战）常常给两笔同名同形的笔画选项**
证据：`tests/logs/review/dup_missing.png`：火缺一撇，选项是 "丶、丿、丿"——两个撇只差长短；`tests/logs/shots/P_huluwa_quiz.png`：选项里两个一模一样的横。用出题函数生成 1000 题，291 题（29%）的错项里有一笔与答案同名（`rv_gen.json` missing_dups）；代码还特意把"同一个字的另一笔"放进错项（`games.js` QMissing.gen 的 sameOther），山缺一竖时另一竖就是错项。4 岁孩子分不清"哪一根撇"，这题变成猜。
→ 建议：错项的笔画名必须与答案不同、彼此也不同；不要用同字的另一笔；卡片上把笔画按在字里的实际大小和位置画出来（现在每张卡单独裁切放大，长短信息也丢了）。

**[中等] R1-03 四个字的笔画名念错**
证据：`src/writer.js` STROKE_NAMES：禾 "撇 横 竖 撇 **点**"、米 "点 撇 横 竖 撇 **点**"、休 "撇 竖 横 竖 撇 **点**"、小 "竖钩 **点** 点"。标准笔画名：禾、米、休的最后一笔是**捺**（字形数据本身也是捺，见 `tests/logs/shots/L_paw_write.png` 米的右下角），小的第二笔是**撇**。写对这一笔时孩子听到的正是这个错名字（录音里"点""捺""撇"都有，所以不是录音问题，是表写错）。
→ 建议：改这四条；加一条自测，把 STROKE_NAMES 和一份权威笔画表（或按中线方向自动判定撇/捺/点）对一遍。

**[中等] R1-04 认字的难度阶梯缺一级：L1 和 L2 完全一样，L3 以后卡住再久也不给图**
证据：`rv_gen.json` find_levels：L1 和 L2 都是 3 选 1、任务卡都有图片（`games.js` FindBase.present：`st.level <= 2` 就放图）。设计说 L2 是"只听声音，提示时才出现图片"，没有实现。L3 直接变成 4 选 1 + 形近字（日/目/田）+ 任务卡只剩一个眼睛图标。真实时长不操作 62 秒（`tests/logs/review/r_idle_bluey_find.png`，`rv_rules.json` idle_bluey:find）：提示阶梯只是重复"哪个是月？"和鼓励语，没有任何图片出现。一个 4 岁孩子在 L3 不认识这个字时，没有任何可以"推理"的东西，只能点一个试试——而第一次点错星星就没了。
→ 建议：按设计做 L2（只听、提示 2 级时任务卡出现图片）；L3–L5 在提示 2 级（10 秒）后也让图片出现。这不替孩子做，只是把"题目"说完整。

**[中等] R1-05 "读单词"（能量站挑战）卡片上的字母互相叠在一起**
证据：`tests/logs/review/read_words_L.png`、`tests/logs/shots/P_robot2_quiz.png`："egg" 的两个 g 叠在一起、"pen" 的 p 和 e 粘连、"bag" 同样。量过（`rv_gen.json` read_overlap）：相邻字母包围盒重叠 21 px（字母宽 45 px，重叠近一半），原因是 `games2.js` QRead.present 给每个字母 `margin: 0 -9px`。这是教孩子"读"的那一屏，字却最难看清。
→ 建议：去掉负边距，字母改小一号（70 左右）并排即可；三字母单词卡 190 px 宽放得下。

**[中等] R1-06 岛面板里主持人的头被屏幕上沿切掉**
证据：`tests/logs/screens/L_panel.png`（1180×820：佩奇的头顶和耳朵被切）、`tests/logs/review/panel_1024.png`（1024×768：奥特曼头顶贴边）。算法在 `app.js` openPanel：hero top = cy − S·0.48，横屏时为 −33 px / −31 px。竖屏没问题（149 px）。
→ 建议：横屏时把岛和主持人整体下移或把 S 换成 min(vw, vh)·0.9；加到 test_layout 里（面板现在没被检查）。

**[轻微] R1-07 "哪个写对了"的翻转字形掉到卡片下半截**
证据：同 R1-01 的两张截图，翻转/旋转的字母都比正的低一截。原因是 `transform: scaleY(-1)` 绕 svg 中心（viewBox 高 140、字母只占 0–80）。即使 R1-01 修好，这个位置差也是一个"看位置就知道哪个不对"的漏洞。
→ 建议：`transform-origin` 设到字形包围盒中心，或在 `Glyph.en` 里按字形居中。

**[轻微] R1-08 字宝盒封面少了设计里的两条世界进度条**
证据：`tests/logs/screens/L_book.png`、`P_book.png`：只有"3 个字 · 2 个字母"一行；DESIGN.md §5 说封面写"我认识 23 个字"并配第一、第二世界的进度条。孩子看不懂数字，进度条才是他看得懂的"越攒越满"。
→ 建议：加两条按岛分段的进度条（14 段），满一段亮一格。

**[轻微] R1-09 "字从画里来"不是"一笔一笔写"，是一笔一笔"浮现"**
证据：`tests/logs/review/r_meet_1.png`–`r_meet_3.png`：目的笔画依次淡入，没有毛笔、没有沿笔画方向的书写感；写字游戏里的毛笔示范（`Writer.demo`）就在旁边却没复用。效果不差，但比设计承诺的弱，也少了一次免费的笔顺示范。
→ 建议：第一次见字时直接用 `Writer.ink` 沿中线刷出，加毛笔。

**[轻微] R1-10 "缺了一笔"大字格里被挖掉的那一笔用红色虚线描出轮廓**
证据：`tests/logs/review/dup_missing.png`。等于把答案的形状和位置画在了题面上，孩子只需要配形状，不需要知道这个字缺什么——这也是为什么同名同形的错项（R1-02）特别致命。
→ 建议：L1–L2 保留虚线（当作脚手架），L3 起只留空白。

## 3. 抽查了什么

**写字（核心）**，真实时长，横竖屏各一遍（`tests/logs/review/w_*`）：
- 葫芦山 写字 L1（火）：开场"写一写！→ 火，火苗的火！→ 看我写一遍 →（毛笔逐笔示范）→ 该你写啦！"，一句不少（`rv_write.json` zh_L1_intro_said）。示范时毛笔跟着笔画走、笔画橙色点亮（`w_L_zh_L1_demo.png`）；轮到孩子时绿点带编号、蓝色流动箭头、橙色呼吸高亮，4 岁孩子看得懂（`w_L_zh_L1_cues.png`）。
- 第一笔写对：墨迹沿笔画刷黑，说"点"；第二笔倒着写：淡掉、说"跟着箭头写"（`w_L_zh_L1_slip_back.png`），正确；再用抖动 ±4.5% 画框、起点偏 5% 的"手指不准"笔画：通过、不说话、k 从 1 到 2（sloppy_L）。写完：字发光，火苗从字里冒出来跳动，说"火，火苗的火！"（`w_L_zh_L1_alive.png`），有过一次失误这题不给星（stars_after_slips = 0）。
- L3（只有底字）、L5（空田字格；写错一笔后出现绿点 + 箭头 + 这一笔的示范，`w_L_zh_L5_slip.png`）。
- 判笔矩阵（12 个字全部笔画）：倒写 0 笔通过、整体右移四分之一格 0 笔通过、大幅抖动的正确笔画多数通过（`rv_write.json` judge_matrix）；STROKE_NAMES 与字形笔画数全部一致（names_vs_strokes 空）。
- 字母：B 的 L1 示范和线索（`w_L_en_L1_cues.png`）、D 写完皮球弹出（`w_L_en_L1_alive.png`）、小写 f 的 L2 线索（`w_L_lo_L2_cues.png`）。四线三格的字母写法（A 三笔、B 两笔、f 的横最后写）符合小学标准。
- 字宝盒练字：点"手"进练字，三朵小红花、金边；练完回到字宝盒并聚焦那张卡（`w_L_book_after.png`）。

**认字 14 种和挑战 14 种**：每个岛 4 个小游戏 × 两个方向的首题截图全部看过（`tests/logs/shots/`，112 张），重点看了泥坑、气球、葫芦、土堆、草丛、小怪兽、停车场、书包、找一找、星星、合体、花盆、筋斗云、能量块 14 种认字，和翻翻乐、字母排队、缺了一笔、听音找字母、连一连、哪个写对了、听英文、拼单词、大小写、组词、合体字、找部件、小写排队、读单词 14 种挑战。任务靠"任务卡上的图 + 一句话语音"能看懂（L1–L2）。第一次见字（`r_meet_*.png`）：画面罩一层、东西出现、红字浮现、"看，它变成字！→ 目，眼睛就是目！→ eye"。答对揭晓（佩奇跳泥坑溅泥水、气球变成东西、怪兽变星星……）；答错那句话全部 28 个游戏跑了一遍（`rv_rules.json` wrong_lines）：都是"口，开口的口！/ C, cat! / 它翻跟头啦 / 放上去不对哦"这类就事论事的一句，接"再试一次！"，没有"你错了"、没有红叉、没有失败音。玩法有两对接近：大黄蜂"听英文找东西"和"读单词"都是听词选，星星和筋斗云、葫芦和花盆都是"点对的容器开出东西"，但主题不同，不算重复。

**铁则**：
- 真实时长不操作 62 秒，认字 / 写字 / 挑战各一次（`rv_rules.json` idle_*）：ops、childOps、写字的 k、submitted 全部不变，只有 5 / 10 / 15 秒的三级提示（重说题目、主持人招手、写字时示范当前这一笔）和之后每 20–45 秒一句鼓励 + 重说题目，没有一次替孩子点或写。
- 故意答错（28 个非写字游戏各 1 次 + 佩奇认字真实时长 1 次）：全部换新题、星星为 0；写字倒写一笔后写完整字：不给星。
- 语音 530 句全有录音：`window.__vmiss` 跑完所有游戏为空；按 tools/voice_lines.py 的全集逐句对 bank 哈希，无缺失；中文句子最长 8 字。真实时长下开场、题目、提示都说到（见上）。英文读音的准确性无法在这里听，只能确认字母名是单独录的（"A"、"F" 等 0.36–0.44 s 的短句）和 "A, apple!" 两段都存在。
- 点按目标：56 个游戏 × 两个方向、L5 的最小选项短边 127–230 px（`rv_gen.json` target_sizes_min）；test_layout 四个尺寸全部通过。家长面板在长按齿轮后，短按只出一行提示。

**进度和成就感**：星槽 5 颗、第 5 颗"集满啦！"、岛面板（4 个游戏 + 5 颗小星 + 旗子 + 这个岛的 8 个字灰 → 彩，`L_panel.png` / `P_panel.png`）、地图旗子和云飞走、第一世界插满后庆典岛开、大结局全体合影（`L_finale.png` / `P_finale.png`，28 个角色都在）、门变金、去星光海（`L_map_w2.png`）。这一整条链 test_core 走通，截图里也都看到了。

**视觉**：除 R1-05、R1-06、R1-07 外，没有发现被挡、裁切、重叠。写字的田字格横屏 500 px、竖屏 560 px，很大；认字选项卡上的字 80–110 px。

**新角色**：奥特曼、赛罗、擎天柱、大黄蜂与原有角色并排（首页、大结局、机器人岛）：同样粗黑描边、Q 版比例，放在一起不突兀；新角色略更"立体光泽"，可以接受。

**既有测试**：test_layout L / P / L2 / P2 全部 PASS；test_core、test_pointer、test_voiceflow 的结果见文末。
